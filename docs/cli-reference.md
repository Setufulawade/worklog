# CLI reference

Complete command surface as implemented in `worklog/cli.py` (`build_parser`). This is the
normative reference; the README is the tutorial.

```
worklog [--version] [command] [options]
```

Running `worklog` with no command is equivalent to `worklog add` for today and opens the
interactive prompt. `worklog --help` and `worklog <command> --help` are generated by `argparse`.

---

## Global options

| Option | Effect |
|---|---|
| `--version` | Print `worklog 0.1.0` and exit 0 |
| `-h`, `--help` | Usage for the program or the current subcommand |

## Date arguments (`-d`, `--date`)

Used by `add`, `view` and `edit`. Default `today`. Accepted forms, in the order
`dates.parse_date` tries them:

| Input | Result |
|---|---|
| `today`, `t`, empty | Today |
| `yesterday`, `y` | Today − 1 day |
| `tomorrow` | Today + 1 day |
| `+N`, `-N` | Today ± N days (`-3` is three days ago) |
| `YYYY-MM-DD` | That date |
| `DD-MM-YYYY` | That date |
| `DD/MM/YYYY` | That date |
| `YYYY/MM/DD` | That date |

Anything else raises `ValueError`: `worklog: Could not understand date '…'. Use YYYY-MM-DD,
DD-MM-YYYY, 'today', 'yesterday' or an offset like -2.` and exit code 1. Note that `DD-MM-YYYY`
is accepted alongside `YYYY-MM-DD`, so an ambiguous string like `03-04-2026` is read as
3 April 2026 (the `%Y-%m-%d` parse fails first), not 4 March.

## `worklog add`

```
worklog add [-d DATE] [TEXT ...]
```

Three modes, chosen in this order:

1. **TEXT given** — the arguments are joined with single spaces and stored as **one** entry:
   `worklog add Fixed the login bug` → `Fixed the login bug`. Quote arguments you want to keep
   separate: `worklog add "Fixed login" "Reviewed PR"` is still one entry.
2. **stdin is not a TTY** — every line read from stdin becomes one entry; blank lines are
   dropped. This is the scripting mode: `printf 'a\nb\n' | worklog add`.
3. **otherwise interactive** — prints the date and any existing entry count, then prompts
   `> ` for one entry per line until an empty line, Ctrl-D or Ctrl-C. Each line is written
   immediately, so nothing typed so far is lost on interruption. Prints
   `Saved N entries to YYYY-MM-DD.` or `Nothing added.`

In modes 1 and 2 the confirmation goes to stdout; progress and other diagnostics go to stderr.

## `worklog view`

```
worklog view [-d DATE]
```

Prints the weekday and long date, then a right-aligned number per line (`   1. entry`), or
`  (no entries)`. Read-only: never creates a file, never rewrites one.

## `worklog edit`

```
worklog edit [-d DATE]
```

Creates the day file if missing, opens it in `$VISUAL`, else `$EDITOR`, else `nano` if
installed, else `vi`, then normalises the file — blank lines are stripped and an emptied file
is deleted. Prints `Saved YYYY-MM-DD.` even when nothing changed.

The editor is launched through the shell as `"$EDITOR" "<path>"`, so editor commands with
arguments (`code -w`, `emacsclient -c`) work; the path is quoted.

## `worklog calendar` (alias `cal`)

```
worklog calendar [MONTH]
```

Requires an interactive stdout; with a pipe or redirect it exits with
`The calendar needs an interactive terminal.`

`MONTH` accepts `YYYY-MM` (or `YYYY-M`) as a starting month, otherwise it is parsed as a date
(`worklog cal yesterday` starts on that date's month). Default: this month. The cursor starts on
the first day of that month when `YYYY-MM` is given, otherwise on the parsed date.

Keys:

| Key | Action |
|---|---|
| arrows, `h` `j` `k` `l` | move one day / one week |
| `n`, PgDn | next month (day-of-month clamped to the shorter month) |
| `p`, PgUp | previous month |
| `t` | jump to today |
| Enter, `v` | open the day full screen |
| `e` | edit the day in `$EDITOR` (curses is suspended and restored) |
| `a` | append entries; empty line finishes |
| `q`, Esc | quit |

In the full-screen viewer: up/down or `j`/`k` scroll, `e` edits, `a` appends, `q`/Esc/Enter
returns. `Esc` responds within 25 ms because `run()` sets `ESCDELAY`.

## `worklog report`

```
worklog report {weekly|monthly|yearly} [-p PERIOD] [-o FILE]
```

| Option | Meaning |
|---|---|
| `-p`, `--period` | Period selector, see the table below. Default: the current period |
| `-o`, `--output` | Write the Markdown here instead of the default location |

Default output: `<data_dir>/reports/<kind>-<slug>.md`, with `<slug>` derived from the period
label (see [data-model.md](data-model.md#3-report-files)). The report is printed to stdout in
full **and** written to the file; the save path is announced on stderr as `[saved to …]`, so
`worklog report weekly > week.md` also works.

| Kind | Accepted `--period` values |
|---|---|
| `weekly` | `this`, `last`, `YYYY-Www` (e.g. `2026-W47`), or any date string |
| `monthly` | `this`, `last`, `YYYY-MM` |
| `yearly` | `this`, `last`, `YYYY` |

Requires an API key (see [security-and-privacy.md](security-and-privacy.md)). A period with no
entries fails with `worklog: No log entries found for <label>.` and exit 1 — no file is created
and no API call is made.

## `worklog ppt`

```
worklog ppt {weekly|monthly|yearly} [-p PERIOD] [-o FILE] [--no-ai]
```

| Option | Meaning |
|---|---|
| `-p`, `--period` | Same values as `report` |
| `-o`, `--output` | Output `.pptx` path. Default: `./worklog-<kind>-<slug>.pptx` in the current directory |
| `--no-ai` | Build the deck from the logs deterministically, with no API key and no network call |

Prints `Created <path>  (N slides)`. Requires `python-pptx`; if it is missing the command exits
with instructions to `apt install python3-pptx` or `pip install python-pptx`.

Deck structure, always: 1 title slide, 1 stats slide (days logged, entries, longest streak,
busiest day), then the content slides. With AI, content follows the 6–8 / 8–10 / 10–12 slide
plan for weekly / monthly / yearly. With `--no-ai`, weekly is one slide per logged day, monthly
one per ISO week, yearly one per month; more than 7 bullets spill onto a `(cont.)` slide, and
a yearly month is capped at 6 bullets plus an `...and N more entries` line.

## `worklog config`

```
worklog config show
worklog config path
worklog config set KEY VALUE
```

| Action | Output |
|---|---|
| `show` | Config file path, then every key; `api_key` is masked |
| `path` | The config file path only (useful for backups or `$EDITOR`) |
| `set` | Validates and persists one key, then prints `Set KEY.` |

Valid keys and their constraints:

| Key | Validation |
|---|---|
| `provider` | Must be `anthropic` or `openai`. Switching also updates `model` if it was still the previous provider's default |
| `model` | Free text, not checked against the provider |
| `api_key` | Stored in the mode-0600 file; environment variables still take precedence |
| `base_url` | Free text; empty restores the provider default endpoint |
| `max_tokens` | Parsed as an integer; a non-numeric value exits 1 with Python's `int()` message |

An unknown key exits with `Unknown key '…'. Valid keys: provider, model, api_key, base_url,
max_tokens`.

## Environment variables

| Variable | Read by | Effect |
|---|---|---|
| `WORKLOG_HOME` | `storage.data_dir`, `storage.config_dir` | Overrides **both** roots with one path. Primary use: tests and portable installs |
| `XDG_DATA_HOME` | `storage.data_dir` | Base for `…/worklog` log and report storage |
| `XDG_CONFIG_HOME` | `storage.config_dir` | Base for `…/worklog/config.json` |
| `WORKLOG_API_KEY` | `config.get_api_key` | API key, highest precedence, any provider |
| `ANTHROPIC_API_KEY` | `config.get_api_key` | Key for provider `anthropic` |
| `OPENAI_API_KEY` | `config.get_api_key` | Key for provider `openai` |
| `VISUAL`, `EDITOR` | `calendar_ui._editor` | Editor for `edit` and the calendar's `e` |
| `ESCDELAY` | `calendar_ui.run` | Set to `25` if unset, so Esc quits promptly |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success, including `--help`, `--version`, and a report that printed fine |
| `1` | Expected failure: bad date or period, no entries, unknown config key, AI error, missing `python-pptx`, calendar without a TTY |
| `130` | Interrupted with Ctrl-C |

Failure messages are one line on stderr prefixed `worklog: ` (except the two `SystemExit`
messages, which have no prefix). No tracebacks are shown for expected errors.

## Interaction with pipes

| Command | Behaviour when piped |
|---|---|
| `add` (no TEXT) | Reads entries from stdin instead of prompting |
| `view`, `report` | Plain stdout, suitable for `less`, `grep`, redirection |
| `edit` | Passes the terminal through to the editor; do not pipe |
| `calendar` | Refuses to start |
| `ppt` | No terminal needed |
